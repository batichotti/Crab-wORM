# Crab-wORM

Crab-wORM generates a **PostgreSQL schema** and **HTML forms** from your Rust `structs` and `enums`. You describe your types once, with `#[derive(crab_worm)]`.

> Leia em português: [README.pt.md](README.pt.md)

```rust
use crab_worm::crab_worm;

#[derive(crab_worm)]
pub enum Worm {
    LysareteBrasiliensis,
    StrongyloidesStercoralis,
}

#[derive(crab_worm)]
pub struct Claw {
    pub side: String,
    pub size_cm: u16,
}

#[derive(crab_worm)]
pub struct Crab {
    pub name: String,
    pub age_years: u8,
    pub is_alive: bool,
    pub worm: Worm,             // enum -> FK to the "worm" table
    pub nicknames: Vec<String>, // list -> child table "crab_nicknames"
    pub claws: Vec<Claw>,       // list of structs -> child table "crab_claws"
}
```

From that you get:

- `generate_sql()`: the `CREATE TABLE` statements for every type, already in dependency order.
- `generate_html()`: a complete page (CSS + forms + JS) that saves data through [PostgREST](https://postgrest.org).

## How it works

`#[derive(crab_worm)]` registers each type's metadata (name, fields, types) in a global collection using [`inventory`](https://crates.io/crates/inventory). The generators walk that collection and produce SQL and HTML.

```
Crab-wORM/
├── core/      # crab-worm-core: metadata (meta.rs) and generators (factory.rs)
├── macros/    # crab-worm-macros: the #[derive(crab_worm)] macro
├── examples/  # runnable examples (crab.rs)
└── docker-compose.yml   # Postgres 17 + PostgREST
```

| Module | What it does |
|---|---|
| `meta.rs` | `FieldMetadata`, `StructMetadata`, `EnumMetadata`, `TypeMetadata`, and the `inventory` registration |
| `factory.rs` | `to_sql()`, `to_html()`, `generate_sql()` and `generate_html()` |

## Getting started

### 1. Start the database and the API

Create a `.env` file in the project root:

```dotenv
POSTGRES_USER=crab
POSTGRES_PASSWORD=worm
POSTGRES_DB=crab_worm
```

Then start the containers:

```bash
docker compose up -d
docker compose ps        # db should be "healthy"
```

Postgres listens on `127.0.0.1:5432` and PostgREST on `127.0.0.1:3000`.

### 2. Generate the schema and the page

```rust
fn main() {
    std::fs::write("schema.sql", crab_worm_core::factory::generate_sql()).unwrap();
    std::fs::write("index.html", crab_worm_core::factory::generate_html()).unwrap();
}
```

```bash
cargo run --example crab
```

### 3. Apply the schema

```bash
docker exec -i crab-worm-db psql -U crab -d crab_worm -v ON_ERROR_STOP=1 < schema.sql
docker exec crab-worm-db psql -U crab -d crab_worm -c "NOTIFY pgrst, 'reload schema'"
```

The `NOTIFY` makes PostgREST reload its table cache. Without it, new tables return `404 PGRST205`. If the `NOTIFY` has no effect, `docker restart crab-worm-api` does the job.

### 4. Open `index.html` in your browser

Fill in a form and click **Save**.

## Type mapping

### Rust to PostgreSQL

| Rust | PostgreSQL |
|---|---|
| `i8`, `i16`, `u8` | `SMALLINT` |
| `i32`, `u16` | `INTEGER` |
| `i64`, `u32`, `isize` | `BIGINT` |
| `u64`, `usize` | `NUMERIC(20,0)` |
| `i128`, `u128` | `NUMERIC(39,0)` |
| `bool` | `BOOLEAN` |
| `f32` | `REAL` |
| `f64` | `DOUBLE PRECISION` |
| `String` | `TEXT` |
| `char` | `CHAR(1)` |
| `Option<T>` | the column for `T`, without `NOT NULL` |
| `enum` | `{field}_id INTEGER REFERENCES "{enum}"("id")` |
| `struct` | `{field}_id INTEGER REFERENCES "{struct}"("id")` |
| `Vec<T>` | child table `{parent}_{field}` |

Schema details:

- Every struct table gets `"id" INTEGER GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY`. A struct field named `id` is ignored, because the primary key is already generated.
- Identifiers are quoted and in `snake_case` (`User` becomes `"user"`), which avoids reserved words. When querying from `psql`, use `SELECT * FROM "user";`.
- Each enum becomes an `("id", "name")` table populated with its variants. The id is the **variant's position, starting at 1**.
- A `Vec<T>` becomes `{parent}_{field}("id", "{parent}_id", "position", "value")`, with `ON DELETE CASCADE` on the parent. For enums and structs the value column is `value_id` (an FK). `position` stores the list order.
- Tables are emitted in dependency order (enums first, then the structs that depend on them), so the schema applies on Postgres without FK errors.

### Rust to HTML

| Type | Control |
|---|---|
| `String` | text input; the field name refines the type (`email`, `password`, `url`, `tel`), and `description`/`comment`/`notes` become a `textarea` |
| integers | `number` with the type's `min`/`max`/`step` (`u8` runs from 0 to 255) |
| `f32`, `f64` | `number` with `step="any"` |
| `bool` | toggle switch |
| `char` | text input with `maxlength="1"` |
| enum (up to 4 variants) | choice buttons |
| enum (more than 4) | `select` |
| struct | `select` filled from `GET /{table}` |
| `Option<T>` | optional field (no `*`); enums get a "none" button |
| `Vec<Enum>` | checkable buttons, multiple values |
| `Vec<Struct>` / `Vec<scalar>` | repeatable rows with `+ Add` and `×` buttons |

Each enum also shows up as a reference card at the bottom of the page, listing its variants and ids.

## How the form saves

The form saves in two steps, because lists live in separate tables:

1. `POST /crab` with the scalar fields. PostgREST returns the created row, including its `id`.
2. For each `Vec`, one bulk `POST` to the child table (`/crab_nicknames`, `/crab_claws`...) with `crab_id`, `position` and the value.

If any list step fails, the JS deletes the main record (the child rows go away through `ON DELETE CASCADE`).

The API URL is the `API_URL` constant at the top of the generated script (`http://localhost:3000`). For the form to work, the `GET /{table}` endpoint must return `[{ "id": 1, "name": "..." }]`, which is what PostgREST does.

## Troubleshooting

| Symptom | Likely cause |
|---|---|
| `503 PGRST002` | The API cannot connect to the database. Check `docker logs crab-worm-api`; the host in `PGRST_DB_URI` must be the service name (`db`), not `127.0.0.1` |
| `404 PGRST205` (table not found) | The schema was not applied, or the cache is stale. Run the `NOTIFY` or restart the API |
| `400 PGRST204` (column not found) | The HTML was generated with an old version of the generator. Generate it again and reload with Ctrl+F5 |
| `psql: Connection refused` on the host | Port 5432 is not published on the database container. Check the `ports:` entry in the compose file |
| Password or database ignored | Postgres only applies `POSTGRES_*` the first time the volume is initialized. Use `docker compose down -v` to start over (this deletes the data) |
